RBL Studio — Direct x86-64 ASM IDE + CLI
Release: v0.7.2
Base commit: f285840bddf930c2bf95a074e6ca7b9bd620974e
Backend: two targets from one code generator
  - Linux x86-64 ELF : RBL -> ASM -> GNU as --64 -> GNU ld + libc/libm
  - Windows x86-64 PE: RBL -> ASM -> GNU as --64 -> MinGW-w64 gcc + runtime objects

No C source is generated for user RBL programs on either target. The Windows C
compiler builds the Windows platform runtime and shared container runtime, then
acts as the linker driver. The Linux build links the assembly platform runtime
and the shared C container runtime.

Current implementation in v0.7.2:
- Direct x86-64 assembly generation for Linux ELF64 and Windows PE/COFF.
- The bootstrap compiler is one C translation unit (`compiler/rblc_asm.c`)
  containing lexer, parser/AST, analysis and code generation, with conservative
  scalar fast paths and loop-local register allocation; there is no explicit
  RBL IR/CFG.
- Lists, dictionaries, tuples, `null`, identity (`is`), membership (`in`) and
  record-like `struct` declarations with receiver-method syntax.
- Shared C container runtime with conservative mark-and-sweep collection for
  list, tuple and dictionary objects. String allocations are not all reclaimed.
- Built-in `rbl.io`, `rbl.math`, `rbl.string`, `rbl.fs`, `rbl.time`, and
  `rbl.random` namespaces; no source-module import system is implemented.
- 59 direct regression cases plus separate standard-library/input smoke tests.
- Differential runner for comparing the Linux and native Windows paths when
  run on Windows with WSL and MinGW-w64 configured. Random values and current
  working-directory output are compared by exit status only.
- Five-implementation Linux benchmark: RBL, C (-O2), C++ (-O2), CPython and
  hand-written x86-64 assembly over three workloads.
- CLI version reads 0.7.2 from the root VERSION; newly generated user projects
  initialize their own rbl.toml package version to 0.1.0.

New in v0.7.2:
- Documentation reorganized into matching Russian and English Diataxis editions.
- Five-way benchmark methodology corrected so C/C++ runtime workloads cannot be optimized away; results and limitations are documented.
- Windows runtime reports getcwd failures accurately and documents its platform-specific monotonic clock and pseudorandom sequence.

New in v0.7.1:
- Continued support for native Windows PE/COFF builds through MinGW-w64, with WSL retained as an alternative; this backend predates 0.7.1.
- Windows runtime type checking for list/dictionary/tuple/null parameter values.
- More reliable native toolchain discovery, compiler/runtime rebuild handling,
  build caching, console encoding and Windows/WSL diagnostics.
- Compiler fast-path updates for eligible integer leaf comparisons and in-place
  updates to register-held integer locals, with explicit overflow checks retained.
- Expanded regression coverage, including deterministic Game of Life using
  dictionaries and container operations.

New in v0.7.0 (historical baseline):
- Canonical parenthesized block syntax.
- Standard-library built-ins and namespaces for I/O, math, strings, filesystem,
  time and pseudorandom values.
- Decimal floating-point literals and updated IDE indentation/formatting.
- Typed scalar fast paths and loop-local register allocation retained.
