# RBL Studio — RBL 0.8.0 release manifest
# Snapshot: RBL 0.8.0 / 2026-11-10 (wx frontend follow-up, regression and packaging audit)
# Status: UNRELEASED — not published, tagged or distributed; GUI acceptance and source-distribution blockers remain open.

## Version and targets

Repository/compiler version: 0.8.0 (`VERSION` is authoritative).
Runtime ABI: 1.2.0 (`runtime/rbl_abi.h` is authoritative).
Required features: TAGGED_VALUES, SYSV_AMD64, STACK_VALUE_ARRAYS, CONTAINERS,
GC_MANAGED_STRINGS and FSTRING_FORMAT (bit 5).
Targets: x86-64 Linux ELF64 and x86-64 Windows PE/COFF.
User programs compile through the shared C frontend/code generator to native
x86-64 assembly; user RBL programs are not compiled through C.

## Implemented 0.8.0 scope

- Compiler split into common.c, lexer.c, ast.c, parser.c, sema.c, codegen.c
  and driver.c, with private declarations in compiler/rblc_internal.h.
- Open-addressed indexes for variables, functions and string constants;
  source order and last-definition-wins function behavior are preserved.
- Versioned Runtime ABI descriptor/startup handshake and link-time major guard.
- Canonical C declarations for shared container Runtime entry points in
  `runtime/rbl_abi.h`; Linux/Windows build paths enforce missing/redundant
  prototype checks for shared Runtime C objects.
- Source-position diagnostics through lexer, parser, semantic analysis and
  code generation, including UTF-8 and original f-string offsets.
- Runtime-owned dynamic strings integrated with conservative non-moving
  mark-and-sweep collection for strings and containers.
- Deterministic OOM coverage for initial/growing/compacting string registries,
  container registry, mark stack, survivor vector and pre-sweep replacement
  registry; failed collections preserve the heap and can retry.
- Native C ownership limits documented. Runtime state is process-global and
  unsynchronized; only the thread entering generated RBL main is supported.
  There is no pinning/root-handle API, public FFI or multithreaded Runtime API.
- Bounded f-string specs `[[fill]align][width][.precision][type]`, including
  documented conversions, Unicode fill/width, runtime checks and managed output.
- The five-implementation benchmark is exposed as `bench5way`; `bench3way` is
  retained only as a backwards-compatible alias.
- Proven non-allocating integer/Boolean scalar statements and fast loops omit
  redundant GC safe points; allocating statements and unknown calls retain them.
- A dedicated code-generation regression test verifies scalar safe-point elision
  and retained safe points for allocating statements; the full suite runs it.
- Linux/Windows runtime and toolchain paths include ABI, container and format
  objects; the standalone Linux rebuild script builds the complete Runtime.
- RBL Studio's primary desktop frontend is the native C++20/wxWidgets 3.2 /
  Scintilla application in `native/wx-ui/`, paired with `rbl-studio-worker`.
  The former Rust/egui source remains as a legacy reference; when wx is
  unavailable, `RBL_STUDIO_ALLOW_LEGACY=1` permits fallback to a separately
  built executable from a developer checkout. It is not included in the wx
  installer. The primary frontend uses no Chromium, WebView, WebKit or CEF runtime.
- IDE compiler integration uses the existing `tools/rbltool.py` driver with
  argument-safe process creation, streamed output, cancellable process-tree
  termination, unsaved-buffer snapshots and atomic source/settings writes.
- Windows native user-program builds include a private, pruned MSYS2 UCRT64
  MinGW-w64 toolchain under `toolchain/windows-x86_64/`. The 43-file payload
  (21,821,374 bytes) contains GCC driver, GNU assembler/linker, collect2,
  required startup/static libraries, recursively resolved non-system DLLs and
  the applicable upstream license texts, including MinGW-w64 CRT ZPL-2.1,
  statically linked runtime notices and libwinpthread notices. GCC's C frontend, headers, C++ tools, debugger, make,
  MSYS2 shell and LTO plugin are excluded. RBL disables the linker plugin because
  its emitted objects do not use GCC LTO. `tools/package_windows_toolchain.py`
  rebuilds the bundle from a UCRT64 prefix and verifies its SHA-256 manifest.
  Exact package versions and license metadata are listed in
  `toolchain/windows-x86_64/THIRD_PARTY_NOTICES.md`; source-offer and corresponding-
  source compliance review is still required before redistribution.

## Known boundaries, not 0.8.0 blockers

- Conservative stack scanning may retain unreachable allocations when stale
  pointer-shaped words remain in scanned memory; reclamation timing is not
  deterministic.
- Native heap/global storage and non-entry threads are not scanned. No native
  pinning/root-registration API or concurrent Runtime use is supported.
- No general user FFI/plugin ABI, source imports, multi-file compilation,
  package manager, IR/CFG optimizer or whole-function register allocator.
- Linux/Windows clocks, current-directory paths and PRNG sequences retain
  documented platform-specific behavior.

## Worker control-reserve audit — 2026-11-10 19:50

- Independent review found that process-event intake paused at the output
  high-water mark, but protocol-request intake remained active. A burst of
  request acknowledgements/errors could consume the eight reserved control
  slots and trigger output_broken, clearing already accepted pending events.
- Fixed by applying the same high-water gate to request_rx. When pending output
  reaches MAX_PENDING_OUTPUT_EVENTS - CONTROL_OUTPUT_RESERVE, the coordinator
  stops accepting both new protocol requests and process events. The bounded
  input-reader channel then backpressures stdin until output drains. Added a
  worker unit regression for the request gate and a 10,000-frame integration
  regression that stalls stdout, resumes reading and requires every
  protocol_error response plus bye.
