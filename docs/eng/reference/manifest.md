## Reference: `rbl.toml`

The project manifest is a TOML file named `rbl.toml` in the project directory. The current CLI reads `name`, `version` and `entry` from the `[package]` section.

## Format

```toml
[package]
name = "my_app"
version = "0.1.0"
entry = "src/main.rbl"
```

| Field | Required/default | Meaning |
|---|---|---|
| `package.name` | Not required for entry resolution; generated by `new/init` | Project name. |
| `package.version` | Not required for entry resolution; generated by `new/init` | User project version. |
| `package.entry` | Defaults to `src/main.rbl` | Entry source path relative to the project directory. |

The default version of a new project is `0.1.0`; this is not the version of the RBL language/compiler. The RBL version is stored in the repository root `VERSION` file.

## Entry resolution

From the project directory:

1. An explicitly supplied source path takes precedence over the manifest.
2. If no path is supplied, `package.entry` is used.
3. If `entry` is missing, `src/main.rbl` is used.
4. If the selected file does not exist but a root-level `main.rbl` exists, that file is used instead.

## What the manifest does not do

The CLI does not resolve dependencies, download packages, perform lockfile resolution or compile imported source modules. Dependency, target and package-registry fields are not part of the implemented contract in this version.
