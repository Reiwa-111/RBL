# RBL 0.8 — контракт синтаксиса и семантики

Статус: **согласовано с автором языка** (решения приняты в обсуждении 0.8; этот файл — «источник истины» по синтаксису).
Базис: RBL 0.7.0, аддитивно, кроме одного намеренного разрыва (legacy-блоки `{ }` — см. «Разрыв совместимости»).
Проверка: после каждой фазы зелёными остаются 32 регрессии и дифференциальный прогон на обеих платформах.

## 1. Лексика

| Что | Решение |
|---|---|
| Остаток | `a % b` — только для `int`; для `float` — `rbl.math.fmod(a, b)`; `%` для float — ошибка рантайма |
| Числа (int) | `1_000_000`, `0xFF`, `0b1010`, `0o755`. C-стиль `017` **не** восьмеричный (это 17); восьмеричное — только `0o` |
| Числа (float) | `1.5`, `10f`, `1e42`, `1.5e-3`, `6.02e23`, `1e-9f` |
| Комментарии | `//` и `#` — до конца строки |
| Строки | `"…"` с escape-последовательностями; `"""…"""` — многострочные (escapes внутри тоже работают) |
| Escapes | `\n \t \r \\ \" \xNN \uXXXX \UXXXXXXXX`; `\0` и `\x00` — **ошибка компиляции** (строки в RBL NUL-терминированные, встроенный NUL обрезал бы строку) |
| Интерполяция | `f"{expr}"` и формат после двоеточия: `f"{x:.2f}"`, `f"{x:x}"`, `f"{x:>8}"`; литеральные скобки — `{{` и `}}` |
| Литералы | `true`, `false`, `null` |
| `null` | литерал; операции с ним (`null + 1`, `null[0]`, `null.x`, `null()`) — ошибка рантайма; `print(null)` печатает `null`; в `let` совместим с любым типом |

## 2. Операторы

Приоритет (слабый → сильный): `or` → `and` → `== != is` → `< > <= >=` → `in` → `.. ..=` → `+ -` → `* / %` → унарные `- not !` → `(` `[` вызов/индекс.

- `a % b` — как `*`/`/`; **знак берётся от делимого (C/Rust), не как в Python**: `-10 % 3 == -1`, поэтому тождество `a == (a / b) * b + a % b` выполняется для нашего усекающего `/`; переполнение (`INT64_MIN % -1`) и деление на 0 — ошибка рантайма;
- `==` — **глубокое** сравнение (строки по содержимому, массивы/словари/кортежи поэлементно, struct по полям); `is` — идентичность объекта (`null is null` → true);
- `in` — `x in arr`, `k in dict`, `sub in "строка"` (появится вместе с контейнерами, Фаза 2);
- составное присваивание — **строгая форма RBL** (решение автора): `let i += 1`, `let i -= 1`, `let i *= 2`, `let i /= 3`, `let i %= 2`;
- инкременты — `let i++`, `let i--`, `let ++i`, `let --i`; **только отдельным оператором**, не внутри выражений (нельзя `a[i++]`);
- `set` остаётся объявлением, `let` — изменением; короткие формы тоже пишутся с `let`.

## 3. Управление

- Единый цикл — `for` (без `while`):
  - `for (cond) ( … )` — цикл с условием (условие обязано быть `bool`);
  - `for (true) ( … )` — бесконечный;
  - `for (i in 0..10)`, `for (i in 0..=10)` — диапазоны (как сейчас);
  - `for (x in arr)`, `for (i, x in arr)`, `for (k, v in dict)` — коллекции (Фаза 2).
- `break`, `continue` — без меток;
- `switch` — без провала между ветками:
  ```rbl
  switch (x) (
      case 1      ( print("один") )
      case 2, 3   ( print("два или три") )
      case 4..=9  ( print("четыре-девять") )
      default     ( print("другое") )
  )
  ```
- Тернарник — питоновский порядок, условие в скобках: `set label = "взрослый" if (age >= 18) else "ребёнок"`;
- `defer ( … )` — блок выполняется при выходе из функции (нормальный конец, `return`, `raise`), порядок LIFO, переменные читаются в момент выполнения (Фаза 3).

## 4. Данные

- Массивы: `[1, 2, 3]`, `a[i]`, `a[i] = v`, `a.push(x)`, `len(a)`, срез `a[1..3]` — **копия**; отрицательные индексы — **да** (Python-стиль, `a[-1]`); выход за границы — ошибка рантайма;
- Словари: `{"a": 1}`, `d["a"]`, `d["c"] = 3`, `d.get("z", 0)`, `d.keys()`, `d.remove(k)`, `k in d`;
- Кортежи: `(1, "a")`, деструктуризация `set (x, y) = t`, обмен `set (a, b) = (b, a)`, множественный возврат `return a, b`;
- `{}` — словарь; legacy-блоки `{ … }` **отключены**;
- struct и методы с ресивером (классов нет, наследования нет):
  ```rbl
  struct Point ( x int, y int )

  func (p Point) move(dx int, dy int) ( p.x = p.x + dx )

  set p = Point(1, 2)
  p.move(1, 1)
  ```
  создание — `Point(1, 2)` или именованно `Point(x: 1, y: 2)`; структуры **ссылочные** (объекты GC);
  деструктуризация — `set Point (x, y) = p`.

## 5. Типы (только параметры и возврат; у переменных тип выводится)

```
int  float  string  bool  unit  any
[]int   [][]string          {string: int}      (int, string)
int?  Point?  []int?        Point              func (int) int
```

- `any` — для разнородных контейнеров (`[1, "a"]` — это `[]any`);
- **проверка `[]int` на границе вызова — строгая, включая тип элементов** (решение автора; O(n) на вызов);
- проверка типа возврата — как в 0.7, не выполняется (совместимость); включаем позже отдельным флагом.

## 6. Функции

- Лямбда — тело-выражение: `lambda (x) -> x * 2`; типы можно опускать; многострочная форма — существующий `func (x int) int ( … )`;
- захват внешних переменных — **по ссылке** (ячейки);
- значения по умолчанию: `func greet(name string, greeting string = "Привет")`;
- вариадики: `func sum(xs ...int) int`;
- именованные аргументы при вызове: `greet("Аня", greeting: "Здравствуй")`;
- перегрузка — объявление как в C++/C#, но выбор версии **в рантайме по типам аргументов**; ошибка `no overload of 'add' for (int, string)`; операторной перегрузки нет.

## 7. Ошибки, модули, глобалы

```rbl
try ( … ) catch e ( … ) else ( … ) finally ( … )
raise "файл не найден"
raise rbl.error.new("файл не найден", code: 2)

import math
import math as m
from math import sqrt
import "lib/math.rbl"
```
- `catch e` всегда получает объект ошибки со `.message` (строка в `raise` — сахар);
- имя модуля ищется как `math.rbl` по путям из `rbl.toml`; `import "path.rbl"` — по явному пути; `main` допустим только в файле точки входа;
- глобалы: `set counter = 0` на верхнем уровне объявляет, `let counter = counter + 1` меняет; `const MAX = 100` — переприсваивание ошибка компиляции.

## 8. Потоки (Фаза 4) — выбран «настоящий» вариант

Решение автора: **реальный планировщик с состояниями-машинами** (уровень JS/C#), а не `await` поверх потоков.

```rbl
async func load(url string) string ( … )

set t = rbl.task.spawn(load("…"))
set result = await t
set all = await rbl.task.all([t1, t2, t3])
```
- `async` — ключевое слово функции, которую можно `await`-ить;
- `await` — только внутри `async`-функции; приостанавливает задачу, не блокируя поток;
- последствия для рантайма: кадры асинхронных функций живут в куче (продолжения) → GC обязан их сканировать, значит для async-кадров нужны карты (это самая дорогая часть 0.8 и она проектируется вместе с GC в Фазе 2/4).

## 9. Соглашения об именовании (конвенция, не правило языка)

Типы — `CamelCase` (`Point`, `Dog`), функции/переменные — `snake_case` (`read_file`), ключевые слова — строчные, встроенные неймспейсы — `rbl.*`.

## 10. Разрыв совместимости (единственный)

`{}` — литерал словаря, legacy-блоки `{ … }` отключены. Проверено: в активном корпусе (тесты, примеры, бенчмарки) фигурных блоков нет — они есть только в историческом снимке `reference/Rust_v0.1/test.rbl`, который ничем не компилируется. Флаг `--legacy-braces` для старых файлов не делаем (не нужен).

## 11. Одобрено автором (Фаза 1)

- **math-набор добавляется целиком**: `rbl.math.fmod(a,b)` (C-семантика, знак делимого), `log10(x)`, `log2(x)`, `hypot(a,b)`, `degrees(x)`, `radians(x)`, `trunc(x)`, `sign(x)`, `clamp(x,lo,hi)`, `is_nan(x)`, `is_inf(x)`, плюс константы `rbl.math.pi` и `rbl.math.e` (для констант нужна мини-правка парсера: `a.b.c` как значение без вызова). Функции дублируются и как глобальные имена — как уже сделано для `pow/floor/sin/…`.
- **знак `%` подтверждён**: `-10 % 3 == -1` (как C/C++/Java/JS/Rust), чтобы `(a / b) * b + a % b == a` держалось при усекающем `/`.
- **сравнение скоростей после 0.8**: отдельный бенчмарк RBL против C, C++, hand-written ASM и CPython на одинаковых нагрузках (текущий `benchmarks/compare_all.py` — это RBL/CPython/hand-ASM; расширить до C и C++ и обновить методику с baseline).
