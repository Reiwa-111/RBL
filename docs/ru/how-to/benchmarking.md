## How-to: измерение производительности

В репозитории есть два разных набора измерений. Не смешивайте их числа: они решают разные задачи и используют разные workloads.

## Портативный RBL-only benchmark

```bash
python3 rbl.py bench
```

Он работает через текущий backend и выводит build time, полное время запуска процесса, оценку `net` (run минус запуск пустой программы), диапазон времени и размер исполняемого файла. Маленькие задачи могут быть полностью скрыты накладными расходами запуска.

## Пятикомпонентное сравнение

На Linux или в WSL:

```bash
python3 benchmarks/compare_all.py --warmups 2 --reps 10
```

Через CLI:

```bash
python3 rbl.py bench3way --warmups 2 --reps 10
```

Несмотря на историческое имя `bench3way`, текущий runner сравнивает **пять** реализаций: RBL, C `-O2`, C++ `-O2`, CPython и handwritten x86-64 assembly. Нужны GNU `as`, GNU `ld`, C compiler и C++ compiler. Нативный Windows запуск не поддерживается, потому что assembly baseline использует Linux syscalls.

## Как сделать результаты сопоставимыми

1. Сравнивайте результаты только на одной машине, в одной ОС/среде и при одинаковых версиях toolchain.
2. Не меняйте workloads и оптимизационные флаги между запусками.
3. Увеличивайте число прогревов и измерений для публикации результата; указывайте все параметры.
4. Фиксируйте CPU, ОС/ядро, Python, GCC/G++, binutils, backend, число warmup/repetitions и сырые samples.
5. Повторяйте измерения после изменения benchmark-кода или окружения.

Runner включает запуск отдельного процесса в измеряемое время; время сборки RBL выводится отдельно. В текущем пятикомпонентном runner процесс закрепляется за одним CPU, если ОС предоставляет `sched_setaffinity`.

## Как интерпретировать сравнение

C и C++ собраны с `-O2`. Компилятор вправе сворачивать или преобразовывать циклы: например, заменить условный переход на `cmov` или упростить арифметику. В benchmark счётчики итераций передаются нативным программам при запуске, чтобы GCC/G++ не могли заранее удалить некоторые нагрузки целиком; функция `inc` в тесте вызовов отмечена `noinline`.

Это сравнение результатов конкретных workloads, а не универсальная шкала «скорости языков». Разные алгоритмы, структуры данных, распределения типов, I/O, объём памяти, оптимизационные настройки и startup overhead могут изменить соотношение.
