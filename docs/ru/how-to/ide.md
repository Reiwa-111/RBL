## RBL Studio — нативная IDE

Основная desktop IDE RBL Studio — приложение на C++20, wxWidgets 3.2 и `wxStyledTextCtrl`/Scintilla. Отдельный Rust `rbl-studio-worker` управляет compiler/toolchain-процессами через ограниченный NDJSON-протокол. Chromium, Electron и встроенный WebView не используются. Python 3.9+ нужен для backend-действий, но не для отрисовки или запуска GUI.

Рабочий цикл включает многооконный Scintilla editor, дерево проекта, Find/Replace, Find in Files, палитру команд, Quick Open, навигацию по диагностике, вывод задач и интерактивный stdin/EOF. Полноценный language server, семантическое автодополнение, рефакторинги и встроенный debugger пока не реализованы.

## Запуск

Linux:

```bash
bash RBLStudio.sh
```

Windows PowerShell:

```powershell
.\RBLStudio.cmd
```

Основные CMD/VBS/SH launchers выбирают wx GUI и соседний Rust worker из portable-каталога либо по указателю последней успешной сборки. Если wx недоступен, `RBL_STUDIO_ALLOW_LEGACY=1` разрешает переход на отдельно собранный Rust/egui executable из developer checkout; этот binary не входит в installer. В Linux нужны wxWidgets/GTK и рабочая графическая среда X11 или Wayland.

**Сборка для разработки в Windows:** используется MSYS2 UCRT64 wxWidgets 3.2 и закреплённый в репозитории Binutils overlay. `tools/build_wx_ide.ps1` собирает C++ GUI и Rust worker, затем копирует необходимые runtime DLL. При использовании готового portable payload MSYS2 не требуется в `PATH`.

## Работа с документами

- Текстовые файлы любого расширения открываются через **File → Open**. Они также доступны в дереве проекта; сканирование ограничено 1 500 элементами на каталог и 50 000 узлами глобально.
- Текстовые документы поддерживают UTF-8, UTF-8 BOM, UTF-16 LE и UTF-16 BE. При сохранении сохраняются кодировка, BOM и стиль переводов строк (LF, CRLF или CR). Внутри редактора переводы строк нормализованы к LF. Для смешанных LF/CRLF/CR используется первый обнаруженный стиль; если его восстановление превышает файловый лимит, применяется LF.
- Файлы с NUL/binary-контентом, некорректным UTF-8/UTF-16 и неподдерживаемыми ANSI-кодировками не открываются как текст.
- Ограничения документов: 16 MiB на файл, 64 MiB совокупного текста редактора и максимум 32 вкладки. Перед сохранением проверяется точный размер в исходной кодировке, включая BOM и переводы строк. Это защитные лимиты, а не гарантия соблюдения отдельной цели приёмки 512 MiB для всего дерева процессов.
- Подсветку синтаксиса RBL можно включать и выключать в Settings. Другие расширения отображаются как обычный текст. Редактор поддерживает мягкий перенос строк, направляющие отступов, номера строк, размер шрифта и ширину табуляции.
- Save и Save As не ограничивают расширение: можно сохранять `.txt`, `.md`, `.json`, `.py`, `.rs`, `.toml` и другие текстовые документы.
- Создать обычный текстовый документ можно через **File → New Text File**; новый RBL-документ создаётся через **File → New**.

**Компилятор работает исключительно с `.rbl`.** Run, Build, Check и ASM отклоняют файлы с другими расширениями. Обычные текстовые файлы при этом можно открывать и сохранять без переименования или попытки компиляции.

Project Tree заполняется лениво при раскрытии каталога, но само перечисление выполняется синхронно в UI-потоке: медленные сетевые или съёмные каталоги могут временно задержать окно. Find in Files выполняется в отдельном потоке и ограничен 100 000 записей, 128 MiB суммарного сканирования, 2 MiB на файл, 10 000 результатов и глубиной рекурсии 32. Symlink и generated-каталоги исключаются. Клик по результату или диагностике открывает файл и переводит курсор к нужной позиции.

## Панели и настройки

- **Project** — лениво заполняемое дерево проекта, раскрытие/сворачивание папок и ручное обновление.
- **Editor** — горизонтальная полоса вкладок, dirty-маркер, поиск/замена, номера строк, позиция курсора и кодировка.
- **Run / Problems / Console / Search** — отдельные dockable tool windows. Диагностика разбирается из вывода worker, включая сообщения только в stderr, и позволяет перейти к исходной позиции.
- **Command palette** — быстрый доступ к основным операциям без поиска по меню.
- **Settings** — UI-темы RBL Dark, RBL Light, Nord, Monokai и High Contrast; независимая цветовая схема редактора; компактный режим; размер шрифта, ширина табуляции, номера строк, подсветка RBL, направляющие отступов, мягкий перенос строк, автоматические проверки, сохранение перед Run/Build/Assembly и режим Windows toolchain/WSL. Layout окна и workspace сохраняются между запусками.
- **View** — показать/скрыть Project и Run/Output, восстановить исходную компоновку.

Scintilla предоставляет нативное выделение, undo/redo, номера строк, folding, сопоставление скобок и прокрутку по горизонтали/вертикали. При сохранении приложение сохраняет метаданные кодировки и переводов строк поддерживаемых текстовых файлов. Строка состояния показывает workspace, состояние задачи и позицию курсора.

Для структурных блоков RBL доступны маркеры folding и направляющие отступов. Собственный scanner является приближённым и не использует parser компилятора; необычный или некорректный исходный код может сворачиваться иначе, чем его интерпретирует компилятор.

При запуске RBL с `input()` нижняя панель Run показывает строку `STDIN` и автоматически передаёт ей фокус. Введи строку и нажми Enter или **Send**; можно отправлять несколько строк последовательно. Кнопка **EOF** закрывает stdin, чтобы программы, читающие до конца потока, могли завершиться. `print()` и `input(prompt)` сбрасывают stdout, поэтому приглашения и предыдущий вывод видны до следующего ввода.

Команда **Stop** отменяет активную задачу. Worker остаётся запущенным между задачами и перезапускается только при необходимости по lifecycle.

Перед перезаписью приложение проверяет внешние изменения файла и предупреждает, если сохранение разделит файл с несколькими hard links. Project Tree, Find in Files и Save используют ограниченный обход и проверки файловой идентичности. На Linux сохранение существующего файла использует `renameat2(RENAME_EXCHANGE)`; если exchange не поддерживается, операция завершается fail-closed с `operation_not_supported`, без безусловного fallback через `renameat`. Первое сохранение нового файла использует эксклюзивный `linkat`. Windows применяет `ReplaceFileW` с recovery artifacts и проверками identity, но path-based замена target не является полноценным compare-and-swap. Подробности и ограничения — в инженерном аудите.

## Проверка и измерения

Сборка Windows UCRT64:

```powershell
.\tools\build_wx_ide.ps1
```

Сборка Linux/WSL:

```bash
./tools/build_wx_ide.sh
```

Двухчасовой Windows resource acceptance запускается командой `python benchmarks/wx_resource_acceptance.py --duration 7200 --interval 1 --cycle-interval 60 --max-ui-ping-ms 500`. CSV содержит метрики дерева процессов, handles, GDI/USER objects и отзывчивости UI. Методика и контекст измерений приведены в [отчёте по ресурсам IDE](../../../benchmarks/IDE_RESOURCE_USAGE.md). Для диагностики backend используйте `python3 rbl.py doctor` или **Run → Toolchain doctor**.

wx frontend является основной целью launchers/installers, но остаётся **UNRELEASED / RELEASE BLOCKED**. Предварительный resource run на 480 секунд прошёл пороги, но использовал старую ревизию harness; вторая попытка 7 200 секунд завершилась досрочно после task #45 без CSV. Следующий запуск на 480 секунд с усиленным harness завершился с кодом 1 после начального dispatch Run Tests и не создал CSV/verdict. PASS для двухчасового soak текущего RC не заявляется. Acceptance зарегистрированной Windows install/upgrade/uninstall проходит в изолированном HKCU GUID-подразделе. DPI static checks проходят 12/12, но live 125-200% multi-monitor и интерактивная Linux GUI-приёмка остаются непроверенными. Rust worker corresponding-source archive теперь копируется в новые build payloads и устанавливается обновлённым installer; существующие RC-каталоги созданы до этого изменения. Отдельный MSYS2 source bundle остаётся локальным и не включён в runtime package. Written offer или альтернативный способ распространения исходников не прошёл юридическую проверку. cache_bwrite Binutils достижим при обычной записи PE output; CVE-2026-90801 остаётся unresolved. POSIX Save существующего файла завершается fail-closed без atomic exchange; Windows сохраняет path-based replacement race и LOW edge с возможным orphan temp. Актуальные evidence: [инженерный аудит](../explanation/ide-engineering-audit.md) и [release manifest](../../../RELEASE_MANIFEST.txt).

## Известные ограничения

- ANSI/code-page файлы нужно предварительно преобразовать в UTF-8 или UTF-16. Автоопределение кодовой страницы без BOM намеренно не выполняется, чтобы не портить текст неверной догадкой.
- Отображение и редактирование бинарных форматов не поддерживается.
- Подсветка других языков, полноценное автодополнение, symbol index, rename/refactor и debugger пока отсутствуют.
- Для очень больших файлов (>16 MiB) используйте внешний просмотрщик или разделите файл; IDE намеренно отказывается загружать их, чтобы не выходить из заданного бюджета памяти.

## Legacy Rust/egui frontend

Старая Rust/egui реализация сохранена в `src/app.rs` и `src/editor.rs` для
rollback/reference. Если wx executable недоступен, `RBL_STUDIO_ALLOW_LEGACY=1`
разрешает переход на отдельно собранный executable из developer checkout; он
не входит в wx installer payload и не является основным frontend RBL Studio 0.8.0.

Реализация wx frontend, инструкции сборки, исторические записи тестов и
оставшиеся критерии приёмки описаны в [`native/wx-ui/README.md`](../../../native/wx-ui/README.md).
Не распространяйте portable Windows bundle, пока exact corresponding sources
не будут приложены к нему либо применимый source-offer process не пройдёт
юридическую проверку; см. [`wx third-party inventory`](../../../native/wx-ui/THIRD_PARTY_NOTICES.md).
