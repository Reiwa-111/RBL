## RBL Studio — нативная IDE

Основная desktop IDE RBL Studio — приложение на C++20, wxWidgets 3.2 и `wxStyledTextCtrl`/Scintilla. Отдельный Rust `rbl-studio-worker` управляет compiler/toolchain-процессами через ограниченный NDJSON-протокол. Chromium, Electron и встроенный WebView не используются. Локально собранные Windows/Linux application payloads могут включать app-local CPython 3.14.10 для backend-действий; явный `RBL_PYTHON` имеет приоритет. Для разработки из исходного checkout по-прежнему нужен Python 3.9+. Нативный first-run setup wizard проверяет application root, worker, Python runtime и compiler toolchain, сохраняет начальные per-user настройки и может асинхронно запустить платформенный Install / Repair, если доступен полный installer payload. Wizard можно повторно открыть из Settings; source checkout остаётся отдельным development path, если installer payload отсутствует.

Рабочий цикл включает многооконный Scintilla editor, дерево проекта, Find/Replace, Find in Files, палитру команд, Quick Open, навигацию по диагностике, вывод задач и интерактивный stdin/EOF. Полноценный language server, семантическое автодополнение, рефакторинги и встроенный debugger пока не реализованы.

## Запуск

Linux:

```bash
bash RBLStudio.sh
```

Windows PowerShell:

```powershell
.\RBLStudio.cmd
```

Основные CMD/VBS/SH launchers выбирают wx GUI и соседний Rust worker из portable-каталога либо по указателю последней успешной сборки. Если wx недоступен, `RBL_STUDIO_ALLOW_LEGACY=1` разрешает переход на отдельно собранный Rust/egui executable из developer checkout; этот binary не входит в installer. В Linux нужны wxWidgets/GTK и рабочая графическая среда X11 или Wayland.

Для Linux-установки без зависимости от host GTK используй [инструкцию Flatpak](linux-packaging.md). В ней объявлен GNOME Platform runtime, поэтому Flatpak устанавливает GTK внутрь sandbox приложения. Native shell installer по-прежнему требует host GTK 3 runtime.

**Сборка для разработки в Windows:** используется MSYS2 UCRT64 wxWidgets 3.2 и закреплённый в репозитории Binutils overlay. `tools/build_wx_ide.ps1` собирает C++ GUI и Rust worker, затем копирует необходимые runtime DLL. При использовании готового portable payload MSYS2 не требуется в `PATH`.

## Работа с документами

- Текстовые файлы любого расширения открываются через **File → Open**. Они также доступны в дереве проекта; сканирование ограничено 1 500 элементами на каталог и 50 000 узлами глобально.
- Текстовые документы поддерживают UTF-8, UTF-8 BOM, UTF-16 LE и UTF-16 BE. При сохранении сохраняются кодировка, BOM и стиль переводов строк (LF, CRLF или CR). Внутри редактора переводы строк нормализованы к LF. Для смешанных LF/CRLF/CR используется первый обнаруженный стиль; если его восстановление превышает файловый лимит, применяется LF.
- Файлы с NUL/binary-контентом, некорректным UTF-8/UTF-16 и неподдерживаемыми ANSI-кодировками не открываются как текст.
- Ограничения документов: 16 MiB на файл, 64 MiB совокупного текста редактора и максимум 32 вкладки. Перед сохранением проверяется точный размер в исходной кодировке, включая BOM и переводы строк. Это защитные лимиты, а не гарантия соблюдения отдельной цели приёмки 512 MiB для всего дерева процессов.
- Подсветку синтаксиса RBL можно включать и выключать в Settings. Другие расширения отображаются как обычный текст. Редактор поддерживает мягкий перенос строк, направляющие отступов, номера строк, размер шрифта и ширину табуляции.
- Save и Save As не ограничивают расширение: можно сохранять `.txt`, `.md`, `.json`, `.py`, `.rs`, `.toml` и другие текстовые документы.
- Создать обычный текстовый документ можно через **File → New Text File**; новый RBL-документ создаётся через **File → New**.

**Компилятор работает исключительно с `.rbl`.** Run, Build, Check и ASM отклоняют файлы с другими расширениями. Обычные текстовые файлы при этом можно открывать и сохранять без переименования или попытки компиляции.

Symlink и generated-каталоги исключаются. Клик по результату или диагностике открывает файл и переводит курсор к нужной позиции.

## Панели и настройки

- **Project** — лениво заполняемое дерево проекта, раскрытие/сворачивание папок и ручное обновление.
- **Editor** — горизонтальная полоса вкладок, dirty-маркер, поиск/замена, номера строк, позиция курсора и кодировка.
- **Run / Problems / Console / Search** — отдельные dockable tool windows. Диагностика разбирается из вывода worker, включая сообщения только в stderr, и позволяет перейти к исходной позиции.
- **Command palette** — быстрый доступ к основным операциям без поиска по меню.
- **Settings** — UI-темы RBL Dark, RBL Light, Nord, Monokai и High Contrast; независимая цветовая схема редактора; компактный режим; размер шрифта, ширина табуляции, номера строк, подсветка RBL, направляющие отступов, мягкий перенос строк, автоматические проверки, сохранение перед Run/Build/Assembly и режим Windows toolchain/WSL. Layout окна и workspace сохраняются между запусками.
- **View** — показать/скрыть Project и Run/Output, восстановить исходную компоновку.

Scintilla предоставляет нативное выделение, undo/redo, номера строк, folding, сопоставление скобок и прокрутку по горизонтали/вертикали. При сохранении приложение сохраняет метаданные кодировки и переводов строк поддерживаемых текстовых файлов. Строка состояния показывает workspace, состояние задачи и позицию курсора.

Для структурных блоков RBL доступны маркеры folding и направляющие отступов. Собственный scanner является приближённым и не использует parser компилятора; необычный или некорректный исходный код может сворачиваться иначе, чем его интерпретирует компилятор.

При запуске RBL с `input()` нижняя панель Run показывает строку `STDIN` и автоматически передаёт ей фокус. Введи строку и нажми Enter или **Send**; можно отправлять несколько строк последовательно. Кнопка **EOF** закрывает stdin, чтобы программы, читающие до конца потока, могли завершиться. `print()` и `input(prompt)` сбрасывают stdout, поэтому приглашения и предыдущий вывод видны до следующего ввода.

Команда **Stop** отменяет активную задачу. Worker остаётся запущенным между задачами и перезапускается только при необходимости по lifecycle.

Перед перезаписью приложение проверяет внешние изменения файла и предупреждает, если сохранение разделит файл с несколькими hard links. Project Tree, Find in Files и Save используют ограниченный обход и проверки файловой идентичности. На Linux сохранение существующего файла требует `renameat2(RENAME_EXCHANGE)`; файловые системы без поддержки завершают операцию fail-closed с `operation_not_supported`, без безусловного fallback через `renameat`. Это намеренное ограничение доступности ради безопасности; первое сохранение нового файла по-прежнему использует эксклюзивный `linkat`. Подмена destination symlink во время exchange теперь определяется без следования по ссылке, что позволяет безопасно выполнить rollback при совпадении идентичности обеих записей. Windows применяет `ReplaceFileW` с recovery artifacts и проверками identity, но path-based замена target не является полноценным compare-and-swap. Подробности и ограничения — в инженерном аудите.

## Проверка и измерения

Сборка Windows UCRT64:

```powershell
.\tools\build_wx_ide.ps1
```

Сборка Linux/WSL:


Двухчасовой Windows resource acceptance запускается командой `python benchmarks/wx_resource_acceptance.py --duration 7200 --interval 1 --cycle-interval 60 --max-ui-ping-ms 500`. CSV содержит метрики дерева процессов, handles, GDI/USER objects и отзывчивости UI. Методика и контекст измерений приведены в [отчёте по ресурсам IDE](../../../benchmarks/IDE_RESOURCE_USAGE.md). Для диагностики backend используйте `python3 rbl.py doctor` или **Run → Toolchain doctor**.

GitHub Release `v0.8.0-r2` публикует непосредственно source tree соответствующего тега и остаётся опубликованным релизом 0.8.0. RBL Studio 0.8.1 опубликован как [`v0.8.1`](https://github.com/Reiwa-111/RBL/releases/tag/v0.8.1) 2026-11-17. В 0.8.1 добавлены нативный first-run setup/installer wizard и проверенный на Ubuntu 24.04 build wxWidgets GUI + Rust worker с native shell install. Нативный Linux path требует host GTK 3 и host display stack. Flatpak payload и sandbox CLI проверены локально, но GUI/portal path и Flathub publication не объявляются принятыми. Windows SaveDocument прошёл 27/27 на изолированном fixture. Resource smoke прошёл на 60/120/300 секундах с 32 документами, четырьмя типами задач и штатным завершением GUI/worker; 300-секундный запуск завершил 84 цикла. Пользователь подтвердил успешное завершение двухчасового (7 200 секунд) Windows resource soak; он отмечен PASS по подтверждению пользователя. Raw CSV/verdict и финальные хэши GUI/worker в этой рабочей сессии независимо не перепроверялись. DPI static checks прошли 12/12. Live Windows-проверки multi-monitor persistence, восстановления панели, миграции layout и off-screen recovery прошли; пользователь отдельно подтвердил успешную проверку реального mixed-DPI сценария Windows. Запуск на pristine VM не зафиксирован. Эти ограничения раскрыты явно и не выдаются за успешно пройденные тесты. Third-party notices и provenance остаются в репозитории; обязательства при распространении bundled binaries отделены от source-only GitHub publication policy. Binutils 2.47-4 остаётся отмеченным для CVE-2026-90801; описанная область остаточного риска ограничена compiler-generated COFF workflow и не означает исправления upstream finding. Windows `ReplaceFileW` destination-leaf race и POSIX-файловые системы без atomic exchange остаются задокументированными ограничениями; POSIX save работает fail-closed. Актуальные evidence: [инженерный аудит](../explanation/ide-engineering-audit.md) и [release manifest](../../../RELEASE_MANIFEST.txt).


## Известные ограничения

- ANSI/code-page файлы нужно предварительно преобразовать в UTF-8 или UTF-16. Автоопределение кодовой страницы без BOM намеренно не выполняется, чтобы не портить текст неверной догадкой.
- Отображение и редактирование бинарных форматов не поддерживается.
- Подсветка других языков, полноценное автодополнение, symbol index, rename/refactor и debugger пока отсутствуют.
- Для очень больших файлов (>16 MiB) используйте внешний просмотрщик или разделите файл; IDE намеренно отказывается загружать их, чтобы не выходить из заданного бюджета памяти.

## Legacy Rust/egui frontend

Старая Rust/egui реализация сохранена в `rbl-ide/legacy-egui/app.rs` и `rbl-ide/legacy-egui/editor.rs` для
rollback/reference. Если wx executable недоступен, `RBL_STUDIO_ALLOW_LEGACY=1`
разрешает переход на отдельно собранный executable из developer checkout; он
не входит в wx installer payload.

Реализация wx frontend, инструкции сборки, исторические записи тестов и
оставшиеся инженерные критерии приёмки описаны в
[`rbl-ide/wx-ui/README.md`](../../../rbl-ide/wx-ui/README.md). Corresponding-source
archives не являются deliverables или gate для GitHub source release. Храните
[`wx third-party inventory`](../../../rbl-ide/wx-ui/THIRD_PARTY_NOTICES.md) и
применимые license notices в репозитории; обязанности при распространении
бинарных third-party компонентов рассматриваются отдельно.

## Историческая запись приёмки IDE — 2026-11-11

Windows SaveDocument прошёл 27/27 с изолированным fixture. Resource smoke на
60/120/300 секундах прошёл с 32 документами и настоящим path-backed
`resource-task.rbl`; проверялись Check, Build, Run и Tests. Результаты: 85/16,
142/32 и 316/84 samples/task cycles соответственно. В 300-секундном запуске
GUI завершился с кодом 0, worker завершился штатно, максимум Working Set —
282.7 MiB, Private Bytes — 208.0 MiB, UI ping max — 0.9 ms.

Попытка 7 200 секунд завершилась до sampling из-за того, что harness не получил
фокус notebook. Повторный запуск не выполнялся после прямой просьбы пользователя не запускать IDE снова. Это исторический checkpoint от 2026-11-11. Позднее пользователь подтвердил успешное завершение двухчасового soak; текущий статус — PASS по подтверждению пользователя. Pristine-VM и интерактивный Flatpak GUI/portal остаются непроверенными. Историческая попытка не заменяет этот более поздний результат.

В Windows Save исправлен отдельный LOW edge с orphan temp: при ошибке записи,
flush или получения metadata временный файл помечается на удаление через его
ещё открытый handle. Если безопасное удаление не удаётся, путь остаточного файла
выводится пользователю. Path-based `ReplaceFileW` race и CVE-2026-90801 остаются
release blockers. См. актуальный `verification/2026-11-11-Gate-E/GATE_E_REVIEW.md`
и `RELEASE_MANIFEST.txt`.
