## Explanation: принципы дизайна и будущие направления

Этот документ фиксирует проектные решения и отделяет их от текущего language contract. Любая функция ниже, помеченная как идея или roadmap, не считается доступной в RBL 0.7.2.

## Принципы

- Сохранять небольшое и связное ядро языка, не вводя синтаксис без определённой семантики.
- Описывать evaluation order, побочные эффекты, ошибки, платформенные отличия и memory ownership вместе с новыми возможностями.
- Не обещать API, пока нет реализации, tests и стабильных интерфейсов.
- Считать regression suite исполняемым контрактом уже реализованного поведения.
- Разделять загрузку source modules и загрузку нативных расширений IDE/compiler.

## Возможные расширения языка

В обсуждении находятся source modules/import, multi-file compilation, globals/constants, exceptions, `defer`, nullable/container type expressions, slices, negative indexing, named struct construction, lambda/closures, default/variadic/named args, overloads, async/await и format specs f-strings. Точный синтаксис и семантика могут измениться; это не спецификация доступной версии.

## Граница модулей и плагинов

Будущий source import должен включать исходник в текущую сборку программы. Он не должен неявно загружать произвольный код в процесс компилятора или IDE и менять поведение toolchain.

Native extensions/plugins — отдельная система. До её реализации необходимо определить ABI, permissions, lifecycle, compatibility/versioning, failure isolation и допустимые extension points. Нельзя обещать, что плагин заменит parser или code generator без формализованного стабильного интерфейса.

## Что требуется для спецификации новой функции

До реализации следует определить:

1. Грамматику и правила разрешения неоднозначностей.
2. Статические и runtime проверки.
3. Порядок вычисления и видимые побочные эффекты.
4. Ошибки, диагностику и коды завершения.
5. Владение памятью и взаимодействие с collector.
6. Поведение Linux/Windows и ограничения ABI.
7. Regression tests и cross-backend differential tests.
