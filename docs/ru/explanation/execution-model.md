## Explanation: модель выполнения и семантика

Эта страница объясняет несколько менее очевидных свойств RBL 0.7.2. Точные формы выражений см. в [синтаксисе](../reference/syntax.md).

## Функции, аргументы и типы

RBL имеет динамические runtime values и ограниченную проверку объявленных типов параметров. Типы параметров проверяются при вызове. Аннотация return type синтаксически распознаётся, но в текущем runtime не обеспечивает проверку фактического возвращаемого значения.

Количество аргументов функции проверяется до вычисления выражений-аргументов. После этого аргументы вычисляются, и типы параметров проверяются на уже полученных значениях. Поэтому ошибка arity и ошибка типа параметра могут по-разному влиять на наблюдаемые побочные эффекты.

## Переменные и порядок вычисления

`set` и `let` намеренно не являются полностью симметричными:

- `set` сначала убеждается, что имя ещё не объявлено, а затем вычисляет RHS.
- `let` сначала вычисляет RHS, затем проверяет, что имя существует и runtime-тип подходит для присваивания.

Такой порядок означает, что RHS у невалидного `let` может успеть выполниться, тогда как повторный `set` завершается до вычисления RHS.

## Области видимости

Блоки условий и циклов не образуют отдельные lexical scopes: локальные bindings принадлежат общей среде функции. Range-loop variable остаётся привязанной после цикла, если цикл выполнил хотя бы одну итерацию; при нуле итераций binding не создаётся.

## Boolean evaluation

`and` и `or` вычисляют оба операнда. Это не short-circuit evaluation. Выражение справа может выполниться, даже когда логический результат уже известен из левого операнда. Для условного вычисления используйте `if` expression или блок `if`.

## Различие `Unit` и `null`

`Unit` обозначает отсутствие полезного результата функции/выражения и печатается как пустое значение. `null` — отдельный runtime value и печатается буквально как `null`. Их сравнение и поведение различаются.

Отсутствующий dictionary key возвращает `Unit`, а не `null`; наличие ключа проверяется оператором `in`.

## Структуры

`struct` в 0.7.2 — синтаксис для объявления имён полей и receiver-methods, а не полноценная объектная система. Созданный экземпляр хранится как dictionary. Вызов `instance.method(args)` понижается в обычный вызов с receiver как первым аргументом. Receiver type не гарантирует, что переданный объект имеет выделенный runtime class identity.

## Платформенно-зависимые наблюдения

`cwd`, источник времени и псевдослучайные последовательности зависят от платформы. Differential tests должны сравнивать детерминированную семантику, а не требовать байтового совпадения этих конкретных значений между OS.
