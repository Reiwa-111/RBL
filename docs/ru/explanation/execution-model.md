## Explanation: модель выполнения и семантика

Эта страница объясняет некоторые менее очевидные свойства языка и runtime RBL 0.8.0. Ограниченные спецификаторы форматирования f-строк описаны в [справочнике синтаксиса](../reference/syntax.md).

## Функции, аргументы и типы

RBL имеет динамические runtime values и ограниченную проверку объявленных типов параметров. Типы параметров проверяются при вызове. Аннотация return type синтаксически распознаётся, но в текущем runtime не обеспечивает проверку фактического возвращаемого значения.

Количество аргументов функции проверяется до вычисления выражений-аргументов. После этого аргументы вычисляются, и типы параметров проверяются на уже полученных значениях. Поэтому ошибка arity и ошибка типа параметра могут по-разному влиять на наблюдаемые побочные эффекты.

## Переменные и порядок вычисления

`set` и `let` намеренно не являются полностью симметричными:

- `set` сначала убеждается, что имя ещё не объявлено, а затем вычисляет RHS.
- `let` сначала вычисляет RHS, затем проверяет, что имя существует и runtime-тип подходит для присваивания.

Такой порядок означает, что RHS у невалидного `let` может успеть выполниться, тогда как повторный `set` завершается до вычисления RHS.

## Время жизни динамических строк

Строковые values используют общие NUL-terminated byte buffers, неизменяемые на уровне языка. Строковые литералы и константы Runtime имеют статическое хранение; строки из конкатенации, ввода/чтения файлов, преобразований, строковых методов и форматирования контейнеров выделяются в heap и принадлежат Runtime. Присваивание и передача строки копируют tagged pointer pair, а не байты, поэтому aliases указывают на одну аллокацию.

Динамические строки и контейнеры освобождаются консервативным non-moving mark-and-sweep collector. Значение сохраняется, если его точный base pointer встречается как pointer-shaped machine word где-либо в сканируемом диапазоне стека либо оно достижимо через живой list, tuple или dictionary. Сканирование стека не проверяет tag слова. Компилятор вставляет safe points перед операторами, способными выделять память или вызывать код с неизвестным поведением аллокаций, а также при проверках условий циклов. Для доказанно не выделяющих память integer/Boolean scalar statements лишние проверки пропускаются. В доказанно не выделяющем память fast integer/Boolean loop также пропускаются safe points на каждой итерации: внешний statement `for` выполняет проверку перед входом, а следующий потенциально выделяющий память statement — следующую проверку. Runtime allocation helpers не запускают сборку во время вычисления выражения, поэтому временные операнды и возвращаемые значения остаются действительными до завершения выражения. Из-за stale pointer-shaped данных на стеке сборщик может удерживать недостижимые allocations дольше; освобождение не гарантировано на конкретной safe point.

RBL-код не должен вручную освобождать string payload. Сборщик сканирует стек текущего потока до frame pointer, сохранённого из сгенерированной `main`, поэтому pointer, материализованный в stack local native C frame внутри этого диапазона, консервативно считается root, пока frame активен. Native heap/global storage и другие потоки не сканируются. Такое сканирование не является pinning или API регистрации корней: native-код не должен хранить managed pointer только в несканируемом хранилище или после исчезновения всех соответствующих RBL/stack roots. Состояние Runtime глобально и не синхронизировано: 0.8.0 поддерживает только поток, вошедший в сгенерированную `main`; параллельные вызовы из native worker threads не поддерживаются.

## Области видимости

Блоки условий и циклов не образуют отдельные lexical scopes: локальные bindings принадлежат общей среде функции. Range-loop variable остаётся привязанной после цикла, если цикл выполнил хотя бы одну итерацию; при нуле итераций binding не создаётся.

## Boolean evaluation

`and` и `or` вычисляют оба операнда. Это не short-circuit evaluation. Выражение справа может выполниться, даже когда логический результат уже известен из левого операнда. Для условного вычисления используйте `if` expression или блок `if`.

## Различие `Unit` и `null`

`Unit` обозначает отсутствие полезного результата функции/выражения и печатается как пустое значение. `null` — отдельный runtime value и печатается буквально как `null`. Их сравнение и поведение различаются.

Отсутствующий dictionary key возвращает `Unit`, а не `null`; наличие ключа проверяется оператором `in`.

## Структуры

`struct` в 0.8.0 — синтаксис для объявления имён полей и receiver-methods, а не полноценная объектная система. Созданный экземпляр хранится как dictionary. Вызов `instance.method(args)` понижается в обычный вызов с receiver как первым аргументом. Receiver type не гарантирует, что переданный объект имеет выделенный runtime class identity.

## Платформенно-зависимые наблюдения

`cwd`, источник времени и псевдослучайные последовательности зависят от платформы. Differential tests должны сравнивать детерминированную семантику, а не требовать байтового совпадения этих конкретных значений между OS.
