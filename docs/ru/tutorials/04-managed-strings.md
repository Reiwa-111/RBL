# Урок 4: Runtime-managed динамические строки

В RBL 0.8.0 управление временем жизни динамических строк перешло к Runtime. Результаты `input()`, `read_file()`, преобразований и строковых операций являются управляемыми значениями. В исходном коде RBL не нужно вручную освобождать payload строк.

```rbl
func make_message(name string) string (
    return "Hello, " + name
)

func main() (
    set name = "Ada"
    set message = make_message(name)
    print(message)
    print(f"message length: {len(message)}")
)
```

Сборщик консервативный и неподвижный. Он отслеживает управляемые строки и контейнеры в предусмотренных safe points. Публичного вызова `gc()`, API закрепления объектов или многопоточного Runtime API нет. Для нативного C действуют отдельные ограничения заимствования и root management; нельзя считать, что C-код может бесконечно хранить произвольные указатели.

Перед написанием native extensions прочитай [модель выполнения](../explanation/execution-model.md).

**Упражнение:** создай строки несколькими вызовами функций, сохрани их в списке и прочитай после возврата из функций. Не добавляй ручное освобождение памяти.
