# last verified: v0.7.2 | 2026.11.06 | DOCS UPDATE

## Release notes

Заметки ведутся в формате [Keep a Changelog](https://keepachangelog.com/en/1.1.0/): изменения сгруппированы по категориям **Added**, **Changed**, **Fixed**. Здесь перечислены подтверждённые пользовательские изменения релизов 0.7.2 и 0.7.1; импортированная история репозитория до них неполна, поэтому более ранние релизы не реконструируются как полный changelog.

## [0.7.2] - 2026-11-06

### Added

- Полные русская и английская редакции документации, организованные по Diátaxis: tutorial, how-to, reference и explanation.
- Отдельная подробная дорожная карта RBL от 0.7.2 до 1.0 с критериями выхода; модульная система исходников обозначена центральной целью 1.0.
- Документированные результаты пятистороннего Linux-бенчмарка RBL, C, C++, CPython и x86-64 ASM: медианы, отношения производительности, окружение, ограничения и команда воспроизведения.

### Changed

- Корневая `VERSION` стала единственным источником версии репозитория; `rbl.py version` и `rblc-asm --version` сообщают `0.7.2`.
- `rbl new` и инициализация проекта создают независимую версию пакета `0.1.0`, не копируя версию самого компилятора.
- Пятисторонний benchmark теперь передаёт итерации C/C++ программам во время выполнения; вызовная функция помечена `noinline`, чтобы `-O2` не сворачивал тестовый workload в константу.
- Методика benchmark уточнена: измеряется полный запуск процесса, сборка RBL учитывается отдельно; опубликованы исправленные результаты и ограничения трёх синтетических workloads.
- Документация Windows runtime точнее описывает монотонные часы `GetTickCount64`, локальную последовательность PRNG и границы межплатформенной детерминированности.
- Корневой README сокращён до точки входа в актуальную двуязычную документацию; прежние подробные страницы сохранены в архиве.

### Fixed

- Исправлено сообщение Windows runtime: ошибка получения текущего каталога через `getcwd` больше не маскируется под сбой часов.
- Обновлены версия и диагностический текст native compiler: вместо устаревшей строки `0.7.0` выводится `0.7.2`.
- Smoke/regression сценарии файлового ввода-вывода используют каталог `build/` внутри checkout вместо жёстко заданного `/tmp`.

Релизная проверка: 59/59 direct regression tests и standard-library smoke test проходят; CLI и Linux/Windows compiler binaries сообщают `0.7.2`.

## [0.7.1] - 2026-10-05

### Added

- Добавлены regression tests для типизированных параметров-словарей и детерминированная программа Game of Life.
- Прямой regression suite расширен с 57 до 59 сценариев.
- Обновлены Windows/WSL smoke tests и диагностические средства.

### Changed

- Компилятор получил прямое lowering для подходящих integer leaf comparisons и in-place updates register-held integer locals с сохранением проверок переполнения.
- Toolchain кэширует результаты сборки и избегает ненужной пересборки compiler/runtime при неизменившихся входных файлах.
- Windows IDE/toolchain launch paths подавляют временные консольные окна там, где это возможно.

### Fixed

- Исправлена диагностика типов Windows runtime для `list`, `dict`, `tuple` и `null`, передаваемых в typed function parameters.
- Исправлено обновление Windows runtime object при изменении исходника: устаревший объект пересобирается.
- Повышена надёжность Windows launch/process handling, включая UTF-8 console output и пересборку устаревших runtime objects.

## Политика ведения changelog

- Добавляйте запись в категорию `Added`, `Changed` или `Fixed` при изменении пользовательского контракта.
- Описывайте эффект для пользователя, а не только имя изменённого файла.
- Не записывайте proposal/roadmap как уже добавленную функцию.
- Не меняйте исторические числа задним числом без подтверждённого release diff.
- Следующий релиз добавляется выше предыдущего с датой публикации в формате `YYYY-MM-DD`.
