# last verified: v0.8.0 | 2026.11.10 | RELEASE CANDIDATE NOTES

## RBL 0.8.0 — черновик заметок к релизу

Документ описывает пользовательские изменения, подготовленные для RBL 0.8.0. До отдельного решения о публикации это предрелизный черновик. Дата публикации здесь не назначается.

> **Статус IDE на 2026-11-10:** основной frontend RBL Studio — C++20/wxWidgets 3.2 со Scintilla и отдельным Rust worker; прежнее приложение Rust/egui остаётся legacy source. Windows SaveDocument byte-roundtrip acceptance проходит 27/27. Проверка resource soak на 7 200 секунд для текущего RC не завершилась успешно: последняя попытка остановилась раньше времени без CSV/verdict. Live high-DPI/multi-monitor и интерактивная Linux GUI acceptance не подтверждены. CVE-2026-90801 остаётся нерешённой; отдельный MSYS2 source bundle отсутствует в runtime payload; legal review и письменное source offer не завершены; существующие RC требуют пересборки. Эти пункты блокируют binary redistribution. См. [инженерный аудит IDE](explanation/ide-engineering-audit.md) и [отчёт ресурсов](../../benchmarks/IDE_RESOURCE_USAGE.md). Это предрелизная квалификация, не заявление о публикации.

### Added

- Ограниченные спецификаторы форматирования f-строк: символ заполнения, выравнивание, минимальная ширина, точность чисел с плавающей точкой и явные типы преобразования целых, вещественных значений и строк. Грамматика и границы определены в [справочнике синтаксиса](reference/syntax.md).
- Диагностика с именем файла, строкой, столбцом, меткой этапа компилятора, фрагментом исходного кода и кареткой для лексического и синтаксического анализа, семантической проверки и генерации кода.
- Управляемое Runtime время жизни динамических строк, интегрированное с консервативным неподвижным mark-and-sweep collector для строк и контейнеров. Ограничения заимствования строк из нативного C и границы collector документированы явно.
- Дескриптор Runtime ABI и проверка совместимости. Версия ABI независима от версии языка/компилятора; текущая версия Runtime ABI — `1.2.0`.

### Changed

- Компилятор разделён на специализированные C translation units с приватными интерфейсами модулей. Поиск переменных, функций и строковых констант использует hash-индексы, сохраняя детерминированный порядок исходных данных и поведение разрешения имён функций.
- Динамические строки стали объектами, которыми владеет Runtime. Программы на RBL не должны вручную освобождать payload управляемых строк; см. [модель выполнения](explanation/execution-model.md).
- Добавлены safe points для сборки мусора. Для быстрых целочисленных циклов вызовы safe point пропускаются внутри итераций только тогда, когда компилятор доказывает отсутствие аллокаций и изменения указательных корней.
- Система сборки отслеживает compiler modules, приватные заголовки, ABI-исходники и зависимость от версии; отдельные object-файлы поддерживают инкрементальную и параллельную сборку.
- C entry points общего container Runtime централизованы в `runtime/rbl_abi.h`; Linux/Windows bootstrap paths теперь строго проверяют отсутствующие и повторные прототипы.
- Для сравнения пяти реализаций добавлена корректно названная команда/Makefile target `bench5way`; `bench3way` сохранена как alias обратной совместимости, а methodology guide переименован.
- Основной launcher/install target RBL Studio переведён на C++20/wxWidgets 3.2 + Scintilla с отдельным процессом Rust `rbl-studio-worker`. Прежнее приложение Rust/`eframe`/egui сохранено как legacy reference/fallback и не входит в wx installer. IDE открывает поддерживаемые текстовые документы разных расширений, сохраняя поддержку компиляции только для `.rbl`.
- Для редактора уточнены бюджеты памяти, резервирование истории страниц и проверки границ Replace All; обход дерева проекта получил общий лимит сканирования.

### Fixed

- Улучшено отслеживание позиций в UTF-8, для LF/CRLF/CR и фрагментов интерполяции f-строк: ошибки указывают на исходный файл, а не временный фрагмент.
- Ошибки выделения памяти collector стали транзакционными: неудачная сборка мусора сохраняет существующую кучу и допускает повторную попытку. Структуры аллокации проверяются детерминированными OOM-тестами.
- Согласовано форматирование f-строк в Linux и Windows, включая ширину Unicode code points и граничные случаи fill/alignment.
- Исправлены зависимости сборки: Linux rebuild script и обе платформенные toolchain-ветки включают ABI- и formatting-runtime objects.
- Исправлено SysV AMD64 stack alignment в местах вызова libc/helpers из Linux Runtime, включая error exits и общие arithmetic overflow paths; добавлены инструментальный regression harness и статическая проверка control-flow.
- Артефакты сборки изолированы по identity исходника и target backend: одинаковые имена файлов и одновременные WSL/native-сборки больше не используют общие outputs.

## Запись о проверке релизного кандидата

Проверки компилятора/Runtime ниже не означают завершённую приёмку IDE. Текущий статус IDE и незакрытые критерии описаны в [инженерном аудите](explanation/ide-engineering-audit.md).

- Проходят 61/61 direct compiler regression case. Диагностический suite содержит 63 сценария: 45 ошибок исходника, 8 корректных контрольных программ, 4 ожидаемые runtime errors и 6 тестов некорректных UTF-8 последовательностей.
- 83 выбранных source cases проверяются на Linux/WSL и native Windows: для 61 успешно завершающейся программы и 11 ожидаемых runtime-error программ сравниваются exit code/stdout/stderr; 7 ожидаемо отрицательных fixtures отклоняются с одинаковыми diagnostics; 4 программы со случайным/платформенным выводом должны успешно собраться и завершиться, но их output не сравнивается. Все 30 diagnostic differential cases совпадают.
- Все 114 ожидаемо положительных исходников в 53 примерах и 68 compiler-test файлах компилируются и проходят assembler; все 7 ожидаемо отрицательных исходников отклоняются.
- Все 53 примера проходят `check` в native Windows и WSL. Новые примеры A*, SIR, Monte Carlo π и least-squares regression также успешно выполняются в native Windows.
- Проходят Runtime ABI compatibility/startup/symbol и generated fast-call alignment, инструментальная проверка Linux Runtime (158 textual sites / 178 emitted calls в текущем Runtime object), build-cache isolation, string ownership, transactional OOM rollback/retry, native stack borrow и повторный I/O под GC.
- CLI и Linux/Windows compiler binaries сообщают версию `0.8.0`.

Подробные границы проверки и команды воспроизведения приведены в [`RELEASE_MANIFEST.txt`](../../RELEASE_MANIFEST.txt), [руководстве по тестированию](how-to/testing.md), [справочнике Runtime ABI](reference/runtime-abi.md) и benchmark-отчётах.
