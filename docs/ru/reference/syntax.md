# last verified: v0.8.0 | 2026.11.09 | LANGUAGE CONTRACT RECHECK

## Reference: синтаксис RBL 0.8.0

Эта страница описывает синтаксис, реализованный frontend RBL 0.8.0. Ограниченные спецификаторы форматирования f-строк входят в языковой контракт. Предложения будущих версий не входят в эту спецификацию.

## Структура программы и функции

Программа содержит объявления функций и типов `struct`. Точка входа исполняемого файла — `main` без параметров.

```rbl
func add(a int, b int) int (
    return a + b
)

func main() (
    set answer = add(20, 22)
    print(answer)
)
```

Объявление функции имеет форму `func name(parameters) ReturnType (` с последующим телом и закрывающей `)`. Возвращаемый тип необязателен; без явного возвращаемого типа функция возвращает `Unit`, если не возвращает значение. Типы параметров указываются после имён. Параметры проверяются на соответствие объявленным типам при вызове.

Рекурсивные вызовы поддерживаются. Функции не перегружаются по сигнатуре; повторное объявление имени функции в текущем наборе объявлений использует последнее определение (это поведение покрыто тестом `duplicate_functions.rbl`). Аннотация возвращаемого типа разбирается, но в 0.8.0 не проверяется runtime: не считайте её гарантией статически проверяемого return contract.

## Объявление и изменение переменных

```rbl
set count = 10
let count = 11
let count += 4
let count *= 2
let count++
let count--
```

- `set name = expression` объявляет новую переменную. Повторное объявление того же имени — ошибка.
- `let name = expression` изменяет уже объявленную переменную. Неизвестное имя — ошибка.
- Обычное присваивание требует совпадения runtime-типа с существующим значением.
- Составное присваивание `+=`, `-=`, `*=`, `/=`, `%=` доступно с `let`.
- `let name++`, `let name--`, `let ++name` и `let --name` — инструкции, а не выражения.

Блоки не создают вложенных lexical scopes: блоки функции используют общую среду переменных этой функции. `set` проверяет существование имени до вычисления правой части; `let` вычисляет RHS до проверки того, что имя уже объявлено и имеет совместимый runtime-тип. Эта разница может быть заметна при побочных эффектах или ошибках в RHS.

## Типы и значения

Язык динамически хранит значения, но допускает проверки объявленных типов параметров функций. Экземпляры `struct` в runtime представлены словарями, а не отдельными объектами с полноценной системой полей и типов.

| Тип/значение | Описание |
|---|---|
| `int` | Знаковое целое 64-bit. Арифметика с переполнением в проверяемых целочисленных операциях завершается runtime-ошибкой. |
| `float` | Число с плавающей точкой IEEE-754 binary64. |
| `string` | Строка UTF-8, внутри runtime представлена NUL-terminated строкой. Встроенный NUL escape запрещён. |
| `bool` | `true` или `false`. |
| `Unit` | Отсутствие полезного результата; функция без возвращаемого значения возвращает `Unit`. |
| `null` | Отдельное значение, не равное `Unit`. |
| list | Изменяемый индексируемый список значений. |
| dictionary | Изменяемое отображение ключей в значения. |
| tuple | Упорядоченная неизменяемая последовательность значений. |
| struct instance | Запись, представленная в runtime словарём полей; отдельного runtime-типа struct нет. |

Локальные переменные объявляются без аннотации: `set x = 1`. Синтаксис `x: int` для обычных переменных не реализован.

## Литералы

```rbl
set decimal = 17
set separated = 1_000_000
set hex = 0xFF
set binary = 0b1010
set octal = 0o755
set float_a = 1.5
set float_b = 1.5e-3
set legacy_float = 10f
set yes = true
set empty = null
set text = "RBL"
```

Число с ведущим нулём, например `017`, остаётся десятичным. Для восьмеричной системы обязателен префикс `0o`. Подчёркивания-разделители допускаются в числовых литералах. Суффикс `f` также допускается для float-литералов.

## Комментарии и строки

Обе формы комментариев однострочные:

```rbl
// C-style line comment
# hash-style line comment
```

Поддерживаются escape-последовательности `\\n`, `\\t`, `\\r`, `\\\\`, `\\"`, `\\xNN`, `\\uXXXX` и `\\UXXXXXXXX`. Тройные кавычки позволяют записывать многострочные строки.

F-строки поддерживают интерполяцию выражений, экранированные фигурные скобки и ограниченный набор спецификаторов форматирования:

```rbl
set name = "RBL"
set value = 42
print(f"{name}: {value}")
print(f"braces: {{ and }}")
print(f"hex={255:x}, pi={3.14159:.2f}")
print(f"name={name:*>8}")
```

Грамматика спецификатора: `[[fill]align][width][.precision][type]`:

- `align`: `<` (слева), `>` (справа) или `^` (по центру). Необязательный `fill` — ровно одна UTF-8 code point непосредственно перед символом выравнивания; `{` и `}` зарезервированы и не могут использоваться как fill. Пара fill+alignment имеет приоритет, даже если сам fill равен `<`, `>` или `^` (например, `<<6` или `^^7`). По умолчанию используется пробел. Без явного выравнивания числовые преобразования выравниваются вправо, а строковые и default-преобразования — влево. При нечётном количестве символов padding лишний code point размещается справа.
- `width` — десятичная минимальная ширина от 0 до 1 000 000. Она считает Unicode code points, а не UTF-8 bytes или экранные ячейки терминала.
- `.precision` — целое значение от 0 до 17. Оно поддерживается для float; точность для integer и сочетание точности с `s` вызывают runtime error. Если тип float явно не указан, наличие точности включает формат `g`. Для `f`/`F` и `e`/`E` точность задаёт количество цифр после десятичной точки; для `g`/`G` — количество значащих цифр.
- Типы integer: `d` (десятичный), `b` (двоичный), `o` (восьмеричный), `x` (шестнадцатеричный в нижнем регистре) и `X` (в верхнем регистре). Префиксы `0b`, `0o` и `0x` не добавляются.
- Типы float: `f`, `F`, `e`, `E`, `g`, `G`, соответствующие стилям преобразования floating point в C.
- `s` преобразует любое поддерживаемое значение RBL через `str()`.

Если тип не указан, значение преобразуется так же, как при обычной интерполяции через `str()`. Поэтому отсутствие спецификатора и пустой спецификатор (`{value:}`) эквивалентны. Ширина и выравнивание применяются после преобразования. Несовместимый с runtime-типом формат, точность для integer и другие runtime-несовместимые сочетания вызывают понятную runtime error. Некорректная грамматика, неподдерживаемая буква типа, отсутствие цифр после точки и превышение ограничений ширины/точности обнаруживаются parser на этапе компиляции.

Спецификатор разбирается как синтаксис RBL. Начальный `0` является цифрой ширины, а не флагом zero-padding; для заполнения нулями укажи явную пару fill/alignment, например `0>8`. При ненулевой ширине строковый результат должен быть корректным UTF-8, чтобы можно было посчитать code points; без ширины исходные байты строки сохраняются. Вложенные/dynamic specs, sign flags, grouping, locale controls и произвольные printf-строки не поддерживаются. Linux и Windows используют одинаковые правила преобразования и подсчёта ширины в code points. Escape `\\0` не поддерживается: runtime использует NUL-terminated строки.

## Операторы

### Арифметика

| Оператор | Значение |
|---|---|
| `+` | Сложение; также конкатенация строк. |
| `-` | Вычитание. |
| `*` | Умножение. |
| `/` | Деление. |
| `%` | Целочисленный остаток; операнды должны быть `int`. |

Целочисленное деление усекается к нулю. Остаток имеет знак делимого: `-10 % 3 == -1`. Для остатка float используйте глобальную функцию `fmod(a, b)`. Деление и остаток на ноль вызывают runtime error.

### Сравнение и логика

Сравнение: `==`, `!=`, `<`, `>`, `<=`, `>=`.

Логика: `and`, `or`, `not`; `!` — альтернативная запись `not`.

`and` и `or` не являются short-circuit операторами: оба операнда вычисляются. Поэтому выражение справа может вызвать ошибку или произвести побочный эффект, даже если значение слева уже определяет результат обычной булевой логики.

`is` проверяет идентичность значения/объекта, а `==` — равенство. Сравнение списков, кортежей и словарей по `==` рекурсивно сравнивает содержимое; порядок ключей не влияет на равенство словарей. Два различных контейнера с одинаковым содержимым могут быть равны по `==`, но не идентичны по `is`.

### Условное выражение

```rbl
set message = "ok" if (valid) else "invalid"
```

Вычисляется только выбранная ветвь. `if` в такой конструкции записывается на той же строке, что и выражение, к которому относится.

## Условия и циклы

```rbl
if (score >= 90) (
    print("high")
) elif (score >= 60) (
    print("medium")
) else (
    print("low")
)
```

Цикл по диапазону:

```rbl
for (i in 0..5) (
    print(i)
)

for (i in 0..=5) (
    print(i)
)
```

`..` исключает верхнюю границу, `..=` включает её. Поддерживается также цикл по списку и условный цикл:

```rbl
for (item in items) (
    print(item)
)

for (running) (
    if (done) ( break )
)
```

`break` завершает ближайший цикл, `continue` начинает следующую итерацию ближайшего цикла. Вне цикла обе инструкции являются ошибкой компиляции. Форма `for (condition)` повторяет тело, пока условие истинно.

Поддерживается вложенность циклов. `for (x in ...)` принимает диапазон, список или кортеж. Переменная range/list/tuple loop остаётся bound после цикла, если выполнена хотя бы одна итерация; при нуле итераций привязка не создаётся. Длина list/tuple проверяется на каждой итерации, поэтому мутации в теле могут влиять на завершение цикла. Общая итерация словарей и tuple destructuring в заголовке цикла не реализованы.

## `switch`

```rbl
switch (code) (
    case 1 ( print("one") )
    case 2, 3 ( print("two or three") )
    case 4..=9 ( print("range") )
    default ( print("other") )
)
```

`case` поддерживает перечисление значений и диапазоны. `default` задаёт запасную ветвь. Выражение-объект выбора должно быть переменной или литералом; произвольные выражения с побочными эффектами как subject не допускаются, поскольку проверка выполняется при сопоставлении case.

## Списки

```rbl
set values = [10, 20, 30]
print(values[0])
let values[1] = 25
print(len(values))
print(20 in values)
```

Индексация начинается с нуля. Индекс должен быть целым и находиться в границах списка. Списки изменяемы, могут быть вложенными и содержать значения разных типов. `in` в списке и кортеже проверяет непосредственные скалярные элементы; вложенные list/dictionary/tuple при поиске пропускаются, рекурсивного поиска нет. Для словаря `key in dictionary` проверяет наличие ключа. Если справа строка, `in` проверяет наличие подстроки; также доступна функция `rbl.string.contains(text, part)`.

Отрицательная индексация, срезы и конкатенация списков через `+` не реализованы.

## Словари

```rbl
set config = {"mode": "safe", "retries": 3}
print(config["mode"])
let config["retries"] = 4
print("mode" in config)
print(len(config))
```

Проверенные типы ключей: `int`, `float` и `string`. Отсутствующий ключ возвращает `Unit` (`()`), а не `null`; для проверки существования используйте `in`. Равенство словарей глубокое и не зависит от порядка ключей. Порядок печати определяется layout hash table и не является гарантированным контрактом.

## Кортежи

```rbl
set pair = (10, 20)
print(pair[0])
print(len(pair))
```

`(value)` — группировка выражения, `()` — пустой кортеж, `(a, b)` — tuple. Кортежи поддерживают индексацию, длину, вывод и глубокое равенство. Элементы tuple нельзя переназначать. Пустой кортеж не следует путать с `Unit`, который возвращается функцией без значения.

## Структуры и методы-получатели

```rbl
struct Point (
    x int
    y int
)

func (p Point) move(dx int, dy int) (
    let p.x = p.x + dx
    let p.y = p.y + dy
)

set p = Point(3, 4)
p.move(1, 2)
print(p.x)
```

Структура должна быть объявлена до использования. Конструктор принимает по одному позиционному аргументу на поле, в порядке объявления полей. Экземпляр — словарь, индексируемый именами полей; он выводится как словарь. Метод с receiver понижает вызов до обычной функции, где receiver становится первым аргументом. Receiver type не образует отдельного runtime-класса и не проверяется как объектная идентичность.

## Ввод-вывод и стандартная библиотека

Глобальные функции и namespace-функции доступны без `import`. Подробные сигнатуры и платформенные детали находятся в [справочнике стандартной библиотеки](standard-library.md). Source imports и пользовательские модули в этой версии отсутствуют.

## Типовые ошибки и семантические границы

- Повторное `set` и `let` для неизвестного имени — ошибки.
- Передача параметра неверного объявленного типа — ошибка.
- Проверка количества аргументов функции выполняется до вычисления выражений аргументов; проверка типов параметров выполняется после их вычисления.
- `%` с float — ошибка; используйте глобальную функцию `fmod`.
- Индекс нецелого типа либо вне диапазона — ошибка.
- `break`/`continue` вне цикла и диапазон вне заголовка `for` — ошибки.
- `and`/`or` вычисляют оба операнда.
- `null` и `Unit` — разные значения.
- Отсутствующий ключ словаря даёт `Unit`, не `null`.

## Не реализовано

См. [полный перечень ограничений](limitations.md): imports, многомодульная компиляция, глобальные переменные/константы, исключения, `defer`, lambda/closures, named/default/variadic arguments, overloads, async/await, destructuring, slices и negative indexing.
